# Prospective utility study — NOT EXECUTED

Version: November 10, 2026. No engineers recruited, no adaptation time measured, no effect size estimated. This document is a preparation artifact, not a preregistration or a reported experiment.

## Question and conditions

Does an exact-scope evidence record reduce time to a semantically validated batch and incorrect assumptions beyond ordinary documentation and a robotics checklist?

* A: original release documentation and all normal publisher links.
* B: A plus a robotics checklist with the same substantive action-contract questions.
* C: A plus the scoped evidence record, locators and query output.

Record every extra fact visible in B and C. B versus C is needed to distinguish extra information/checklist effects from evidence binding and lookup. Do not hide critical safety or license information in any arm. The present artifact has not been compared with Datasheets, Data Cards, OXE tools or unaided engineers.

## Tasks and assignment

Use sandboxed batch adaptation rather than unreviewed commands to a physical robot. Freeze exact release versions and selected subsets. Use multiple matched tasks requiring resolution of representation, units, frame, timing, actuator order, gripper convention and normalization. A robotics expert must first verify ground truth from an independent implementation/source/controller check. Do not call AI transcription independent ground truth.

After feasibility, freeze the task list, matching rules, condition order, resources and time budgets. Randomize and counterbalance across engineer/task blocks. Use distinct matched tasks across conditions to reduce carryover. Record prior dataset, controller and tool familiarity. Block or model repeated observations by engineer and task/release; more rows or repeated engineers do not create independent releases.

## Outcomes and logs

Primary: active engineering minutes to the first submitted batch passing a blinded, independently prepared semantic checklist. Also retain wall-clock duration and scheduled/unscheduled waiting. Secondary: incorrect assumptions by type, unresolved questions, abandoned/failed attempts, bytes transferred and reasons for timeout. Metered development energy is exploratory and requires an explicit boundary; none is currently available.

Use `utility_attempts_template.csv`. Retain all randomized attempts. A tensor that loads but fails semantic validation is not a success. Preserve code revisions, checker decisions and adjudication reasons. Report timeouts as censored observations and publish completion fractions; do not analyze only completers.

## Analysis and stopping

Run feasibility first to estimate task duration, failure fraction and within-block variability. Then set the confirmatory participant/task counts, minimum effect of practical interest, power or precision rationale, stopping rule, exclusion rules and contrasts before collecting outcomes. No arbitrary sample-size claim is made here. Prespecify paired/block-aware comparisons and uncertainty intervals; report both time and failure outcomes. Keep B-versus-C separate from A-versus-C. Record any deviations.

Human participation requires the relevant institutional research arrangements. Recruitment, consent, expert review and physical trials require people and resources not supplied by manuscript editing. No such steps have been performed in this revision.
